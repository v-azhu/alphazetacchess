# AlphaZetaChess V0.3.4 — Quiescence Search

## Status

**Implementation complete; validation in progress.**

The current repository already contains the V0.3.4 Quiescence Search
implementation in `engine/search.py`. This document is the validation
checkpoint that follows that implementation.

## Goal

Reduce the horizon effect without changing the normal legal-move rules or
the static evaluation function.

At the nominal search horizon:

- quiet positions may be statically evaluated;
- captures continue to be searched;
- a side that is in check has no stand-pat option and all legal evasions are
  searched;
- a hard `quiescence_max_ply` cap guarantees termination.

## Scope

Included:

1. capture-only continuation;
2. check extensions;
3. fail-soft Negamax alpha-beta quiescence;
4. stand-pat evaluation for quiet nodes;
5. optional `use_quiescence` switch;
6. safety cap;
7. compatible TT use for quiescence values where the stored value is
   independent of remaining q-search budget.

Not included:

- capture SEE;
- MVV-LVA;
- checking-move extensions while not already in check;
- quiescence-specific move ordering beyond the current move generator;
- evaluation tuning.

Those belong to later optimization/evaluation work.

## Validation gates

`tests/test_search_v034.py` covers:

- quiet leaf equivalence with the static evaluator;
- a tactical recapture horizon where QS changes the shallow score;
- extra node work on a tactical leaf;
- mandatory resolution of check;
- termination at the configured safety cap.

The exact numeric score of the horizon test is intentionally not frozen:
evaluation semantics are scheduled for V0.4.

## Benchmark

Before marking V0.3.4 COMPLETE, run a controlled A/B benchmark:

```powershell
python tools/benchmark_v034.py --depths 2
```

Then, if the short run is healthy:

```powershell
python tools/benchmark_v034.py --depths 2 3
```

Compare only these configurations:

- V0.3.3-style search: `use_quiescence=False`
- V0.3.4 search: `use_quiescence=True`

Keep:

- same position;
- same depth;
- same PVS setting;
- same TT setting;
- fresh `Board` and `SearchEngine` per measurement.

Record:

- score;
- best move;
- nodes;
- elapsed time;
- NPS;
- node/time delta.

Correctness takes priority over performance.

## Acceptance criteria

V0.3.4 can be marked COMPLETE when:

1. the full pytest suite remains green;
2. horizon test demonstrates that QS actually extends a tactical exchange;
3. check extension is exercised;
4. safety cap terminates;
5. A/B benchmark is recorded;
6. `roadmap.md` is updated with the measured result and known limitations;
7. `PROGRESS_NOTES.md` is updated with an exact next-step handoff.

## Known limitation

Quiescence currently searches all captures rather than using Static Exchange
Evaluation (SEE). This can make tactical leaves expensive. Do not optimize
this prematurely; first establish the baseline and measure the actual cost.
