# AlphaZetaChess V0.3.4 — Quiescence Search

## Status

**COMPLETE.**

The V0.3.4 Quiescence Search implementation in `engine/search.py` has been
validated end to end: the full pytest suite is green, the dedicated
correctness gates in `tests/test_search_v034.py` pass, and the A/B benchmark
required by the acceptance criteria below has been run and recorded.

## Goal

Reduce the horizon effect without changing the normal legal-move rules or
the static evaluation function.

At the nominal search horizon:

- quiet positions may be statically evaluated;
- captures continue to be searched;
- a side that is in check has no stand-pat option and all legal evasions are
  searched;
- a hard `quiescence_max_ply` cap guarantees termination.

## Scope

Included:

1. capture-only continuation;
2. check extensions;
3. fail-soft Negamax alpha-beta quiescence;
4. stand-pat evaluation for quiet nodes;
5. optional `use_quiescence` switch;
6. safety cap;
7. compatible TT use for quiescence values where the stored value is
   independent of remaining q-search budget.

Not included:

- capture SEE;
- MVV-LVA;
- checking-move extensions while not already in check;
- quiescence-specific move ordering beyond the current move generator;
- evaluation tuning.

Those belong to later optimization/evaluation work.

## Validation gates

`tests/test_search_v034.py` covers:

- quiet leaf equivalence with the static evaluator;
- a tactical recapture horizon where QS changes the shallow score;
- extra node work on a tactical leaf;
- mandatory resolution of check;
- termination at the configured safety cap.

The exact numeric score of the horizon test is intentionally not frozen:
evaluation semantics are scheduled for V0.4.

## Benchmark

Measured 2026-08-30 with `tools/benchmark_v034.py` (Iterative Deepening + PVS
+ TT held constant in both arms; only `use_quiescence` toggled).

| Position | Depth | QS OFF | QS ON | Node Δ | Time Δ | Same score/move |
|---|---|---|---|---|---|---|
| initial | 2 | 3.00s / 982 nodes | 5.20s / 1938 nodes | +97.4% | +73.0% | No / No |
| early_development | 2 | 0.52s / 183 nodes | 0.95s / 345 nodes | +88.5% | +85.2% | Yes / Yes |
| central_development | 2 | 1.72s / 622 nodes | 1.54s / 595 nodes | -4.3% | -10.3% | Yes / No |
| initial | 3 | 6.56s / 2782 nodes | 31.48s / 11140 nodes | +300.4% | +379.6% | No / No |
| early_development | 3 | 8.79s / 3745 nodes | 10.66s / 4264 nodes | +13.9% | +21.3% | No / No |
| central_development | 3 | 29.0s / 12288 nodes | 29.0s / 11271 nodes | -8.3% | +0.1% | No / No |

**Reading these results:** node/time cost of Quiescence Search is highly
position-dependent, not a fixed overhead. `initial` at depth 3 is the
expensive case (captures-only leaf search finds a lot to chew on from the
opening's central pawn tension: +300% nodes, +380% time). `central_development`
at depth 3 is nearly free (-8.3% nodes) because the position after the
recorded development sequence happens to have few open tactical lines at the
horizon. This spread is expected and is exactly the motivation for the
`quiescence_max_ply` safety cap and for treating capture-SEE / MVV-LVA move
ordering (explicitly out of scope here, see "Not included" above) as the
next lever if the `initial`-position cost needs to come down before deeper
search depths become practical.

`same(score/move)=False` is common and expected, not a regression: per
`docs/v0.3.5.md`'s "important principle", Quiescence Search deliberately
changes what is evaluated at the horizon, so a different (more tactically
accurate) score or move is the point, not a bug. This is why the acceptance
criteria below ask for the pytest suite and the dedicated correctness gates
to stay green, not for QS-off and QS-on to agree.

2. [x] horizon test demonstrates that QS actually extends a tactical exchange

   `test_quiescence_adds_nodes_on_a_tactical_leaf`);
3. [x] check extension is exercised (`test_quiescence_is_forced_to_resolve_check`);
4. [x] safety cap terminates (`test_quiescence_safety_cap_terminates`);
5. [x] A/B benchmark is recorded (table above);
6. [x] `roadmap.md` is updated with the measured result and known limitations;
7. [x] `PROGRESS_NOTES.md` is updated with an exact next-step handoff.

## Known limitation

Quiescence currently searches all captures rather than using Static Exchange
Evaluation (SEE). This can make tactical leaves expensive. Do not optimize
this prematurely; first establish the baseline and measure the actual cost.
