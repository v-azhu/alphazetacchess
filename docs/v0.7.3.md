# V0.7.3 — UCCI Time Control

## Status

Implemented as the next incremental layer after V0.7.1 cooperative search cancellation and V0.7.2 asynchronous UCCI search.

## Goal

Allow a UCCI frontend to control search by wall-clock time without putting protocol-specific time logic into `SearchEngine`.

## Design

`UCCIEngine` parses the `go` command into a normalized `SearchLimits` object. Time values are stored in milliseconds after parsing.

Supported controls:

- `depth N`
- `movetime N`
- `time N`
- `opptime N`
- `increment N`
- `oppincrement N`
- `movestogo N`
- `setoption name usemillisec true|false`

The UCCI convention used here is that `movetime` is always milliseconds, while `time`, `opptime`, `increment`, and `oppincrement` are seconds unless `usemillisec` is enabled.

## Time allocation

For clock-based searches, the current conservative policy is:

```text
base = remaining_time / moves_to_go
budget = 0.8 * base + 0.05 * increment
budget <= 80% of remaining_time
```

If `movestogo` is omitted, 20 moves are assumed for allocation. The increment contribution is intentionally small in V0.7 so that the engine does not spend most of the clock reserve on a single move. This is deliberately a simple policy rather than an attempt to model tournament time controls perfectly.

## Cancellation

The worker creates a per-search `Event`. When a time budget exists, a daemon `Timer` sets the event after the budget expires. The existing cooperative cancellation path in `SearchEngine` then unwinds the current search safely and returns the best result from the last completed iteration.

The protocol worker owns the final `bestmove` publication. A normally completed search may publish an `info` line followed by `bestmove`; a search terminated by `stop` or by the time budget publishes only the final `bestmove`.

## Scope boundary

This version does not yet implement:

- `infinite`
- node limits
- mate limits
- ponder / ponderhit
- sophisticated tournament time allocation
- search-overhead calibration

Those can be added later without changing the normalized limit representation.

## Testing

Added coverage for:

- normalized time allocation
- `movetime`
- default-second clock units
- `usemillisec`
- automatic cancellation after a fixed move-time budget
- asynchronous `go` response behavior
- final response behavior after explicit `stop`

The repository test suite must be run in the developer's Windows/Python environment before this branch is considered verified.
