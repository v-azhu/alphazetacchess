# V0.9.16 — TT / PVS A/B Diagnostic

## Goal

V0.9.13–V0.9.15 established that search scores can vary substantially with depth and that Quiescence Search can materially change shallow decisions.

V0.9.16 does not modify the engine. It isolates two interacting search components:

- Transposition Table (TT)
- Principal Variation Search (PVS)

The comparison keeps Quiescence Search enabled and Null Move disabled.

## Variants

For each position and depth:

1. FULL — TT + PVS
2. NO_TT — PVS without TT
3. NO_PVS — TT without PVS
4. NO_TT_NO_PVS — neither TT nor PVS

History Heuristic remains enabled in all variants.

## Positions

The benchmark uses the same six positions as V0.9.15:

- initial
- open_position
- tactical_exchange
- mate_in_one
- free_capture
- exchange_trap

## Run

```powershell
python tools/benchmark_search_components.py --depths 2 3 4
```

If acceptable:

```powershell
python tools/benchmark_search_components.py --depths 3 4 5
```

## Signals

For each variant, record:

- elapsed time
- nodes
- NPS
- score
- best move
- state restoration

Then compare every variant against FULL.

The primary diagnostic signal is **best-move difference**. A score difference alone does not establish a search defect.

## Interpretation

- If removing TT changes the best move or removes major score instability, investigate TT probe/store/bound semantics.
- If removing PVS changes the best move or removes instability, investigate null-window/re-search behavior.
- If both components can be removed without changing decisions or the instability pattern, move the investigation elsewhere.
- If removing both changes behavior while each individual removal does not, investigate their interaction.
- Large node/time changes are expected and are useful for performance context, but are not by themselves evidence of a strength improvement.

## Current code areas worth inspecting only if the data points there

The current search uses PVS around null windows, iterative deepening, and a shared TT. QS also uses depth-0 TT entries.

Potential follow-up areas include:

- TT EXACT/LOWER/UPPER bound semantics;
- TT mate-score normalization by ply;
- reuse of depth-0 QS entries;
- PVS re-search conditions and window propagation;
- interaction between iterative-deepening root ordering and cached PV moves.

No implementation change should be made until the A/B result identifies a component as worth investigating.
