# V0.7.4 — Final Audit & Regression Baseline

## Purpose

V0.7.4 is the final audit checkpoint for the V0.7 protocol/search-foundation phase.
It does not add a new search optimization. The goal is to lock down the behavior that
must remain stable before V0.8 changes move ordering and pruning.

## Scope

### 1. Search time-budget semantics

`SearchLimits.time_budget_ms()` has two deliberately different semantics:

- `movetime_ms`: exact requested budget.
- clock-based `time_ms`: conservative allocation of `0.8 * (remaining / moves)` plus
  `0.05 * increment`, capped at 80% of the remaining clock.
- when `movestogo` is absent, 20 moves are assumed.
- a positive clock always produces at least a 1 ms budget.
- `movestogo=0` is rejected.

These are protocol timing policies, not claims about playing-strength optimality.
They are covered by `tests/test_search_limits.py`.

### 2. Search cancellation invariants

The existing V0.7.1 cancellation contract remains unchanged:

- cancellation is cooperative through the search stop event;
- the last fully completed iterative-deepening result remains the safe result;
- if cancellation occurs before depth 1 completes, the engine may fall back to the first
  legal move;
- move/undo state restoration is protected by `try/finally`;
- cancelled/incomplete nodes are not written to the transposition table;
- UCCI emits one final `bestmove`/`nobestmove`, rather than intermediate results.

These behaviors are already covered by the search and UCCI regression tests and are not
reimplemented here merely to increase test count.

### 3. UCCI timing and worker behavior

The UCCI adapter keeps protocol concerns outside `SearchEngine`. A `go` command creates
an asynchronous worker, converts the requested timing fields into `SearchLimits`, and
uses a timer to set the same cooperative stop event used by an explicit `stop` command.
Normal completion publishes `info` followed by `bestmove`; a timed/cancelled search
publishes only the final move result.

The `usemillisec` option controls whether UCCI time fields are interpreted as milliseconds
or seconds. `movetime` is always represented as the already-normalized millisecond budget
inside `SearchLimits`.

## Audit gate

The final local acceptance command is:

```text
pytest -q
```

The V0.7 branch is considered ready for V0.8 only when the full suite is green and the
user's local benchmark baseline has been recorded separately from correctness tests.

## Benchmark baseline

Do not treat test-suite runtime as an engine-strength or search-speed benchmark. Before
V0.8 optimization, record a repeatable search benchmark using the project's existing
benchmark tool and preserve the command, position set, depth, score, best move, node
count, and elapsed time. V0.8 changes should then be evaluated against this baseline,
with correctness and strength evidence kept separate.

## V0.7 exit rule

No additional search optimization is required for V0.7. Once the audit suite is green
and the baseline is recorded, the next development phase is V0.8, beginning with
specialized attack detection and then measured move-ordering improvements.
