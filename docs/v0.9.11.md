# V0.9.11 — Static Exchange Evaluation (SEE)

## Purpose

V0.9.10 added the History Heuristic and established the next classical-search upgrade path. V0.9.11 adds a legality-aware Static Exchange Evaluation (SEE) layer for capture ordering.

## What changed

- Added `engine/see.py` with `StaticExchangeEvaluator`.
- SEE follows the legal capture sequence on the destination square and estimates the net material result of the exchange.
- Recaptures are generated through the existing `Rule.generate_legal_moves`, so pinned or otherwise illegal recaptures are naturally excluded.
- Added `engine/search_see.py` with `SeeSearchEngine`, a thin subclass of `SearchEngine`.
- Capture ordering now prefers the SEE result instead of relying only on MVV-LVA.
- Quiet moves continue to use killer moves and the V0.9.10 History Heuristic.
- The Web UI now instantiates `SeeSearchEngine` with SEE enabled by default.
- Added regression tests covering a clean capture, a forced rook recapture, and board-state preservation.

## Design choice

The base `SearchEngine` was deliberately left unchanged in this checkpoint. SEE is isolated behind `SeeSearchEngine` so that A/B comparisons remain easy and the existing search behavior can be recovered by using the original `SearchEngine`.

This is intentionally a correctness-first implementation. It reuses the existing legal move generator rather than introducing a second attack-generation implementation. If profiling later shows SEE to be a significant fraction of search time, the exchange scan can be optimized independently.

## Expected effect

SEE should mainly improve move ordering in tactical positions where MVV-LVA cannot distinguish a sound capture from a losing exchange. It is not expected to produce a large strength jump by itself. Its larger value is as a foundation for the next search stages, especially quiescence pruning and LMR.
