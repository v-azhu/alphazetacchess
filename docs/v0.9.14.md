# V0.9.14 — Tactical Regression Framework

## Goal

Turn the search-stability observations from V0.9.13 into repeatable tactical checks without pretending that the engine's current answer is ground truth.

The framework uses small positions whose tactical property can be checked independently from the search result:

1. **mate in one** — enumerate legal moves and verify which moves produce checkmate;
2. **free capture** — enumerate captures and verify that the captured piece cannot be immediately recaptured;
3. **exchange trap** — enumerate captures that allow an immediate opponent recapture. The current fixture specifically has Red's rook capturing a Black pawn on `(0,1)` while a Black rook on `(0,2)` can immediately recapture on `(0,1)`.

The framework deliberately reports engine hits rather than turning every position into a hard-coded best-move assertion. A search failure is useful diagnostic information and should not be hidden by a test that simply encodes the current engine's preferred move.

## Files

- `tests/test_tactical_positions.py` — fixture sanity checks and objective tactical-property helpers.
- `tools/benchmark_tactics.py` — runs the engine at multiple depths and reports whether the selected move satisfies the independently computed tactical property.

## Run

From the repository root:

```powershell
pytest tests/test_tactical_positions.py
```

Benchmark the baseline search:

```powershell
python tools/benchmark_tactics.py --depths 2 3 4
```

For comparison with the experimental Null Move pruning:

```powershell
python tools/benchmark_tactics.py --depths 2 3 4 --null-move
```

## Interpretation

- `mate_hit=True` means the engine selected one of the legal immediate mating moves found independently by the fixture checker.
- `free_hit=True` means it selected one of the captures that the checker found to be immediately safe from recapture.
- `trap_hit=True` means it selected a capture that allows an immediate opponent recapture. For the current fixture this is a concrete tactical failure signal, because the recapture wins back the capturing rook after Red takes only a pawn.

These are **tactical gates, not overall strength scores**. A false result does not by itself identify the faulty layer. It narrows the investigation to search horizon, move ordering, quiescence, evaluation, or a combination of them.

The benchmark also checks `state_ok`, because tactical probing temporarily makes and undoes moves. A tactical diagnostic must not corrupt the board state used by the next search.

## Why no hard-coded best-move list yet?

A single engine's output cannot validate itself. For positions without an independent solution, the framework should first establish an objective property or obtain an external/reference solution. Only then should a specific best move be promoted into a regression assertion.

This keeps the V0.9.14 suite useful for diagnosing the existing engine rather than silently teaching the test suite to agree with it.

## Current checkpoint

The first run before formalizing the exchange-trap criterion produced:

- `mate_in_one`: d2-d4 all found an immediate mate;
- `free_capture`: d2-d4 all found the free capture;
- `exchange_trap`: d2-d4 repeatedly selected the immediately recapturable capture `(0,0)->(3,0)` in the original fixture output.

The last result needs to be interpreted together with the exact fixture geometry. The benchmark now explicitly reports `trap_hit` so that this can be tracked as an objective tactical regression rather than inferred from the evaluation score.
