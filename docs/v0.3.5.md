# AlphaZetaChess V0.3.5 — Search Stability & Tactical Regression

## Goal

V0.3.5 establishes regression gates for the search stack before further
evaluation and performance work.

The focus is on invariants rather than forcing one exact best move when
multiple moves can have the same minimax value.

## Scope

- Legal best-move guarantee.
- Determinism for fresh identical searches.
- PVS must preserve the minimax score.
- Transposition-table use must preserve the minimax score.
- Quiescence-enabled search must still return a legal move.

## Important principle

A different best move between Quiescence OFF and ON is not, by itself, a
correctness failure. Quiescence deliberately changes the horizon and may
discover tactical consequences that a nominal-depth search misses.

Likewise, tests should avoid asserting one exact move when several moves have
equal value.

## V0.3 Acceptance Summary

With V0.3.5 complete, the full V0.3 "Strong Traditional Engine" phase is
done. This is the consolidated report the original roadmap asked V0.3.5 to
produce.

| Sub-version | Delivered | Evidence |
|---|---|---|
| V0.3.1 | Iterative deepening + move ordering | `docs/roadmap.md` V0.3.1 table: depth 3 initial position 50s+ → 6.65s |
| V0.3.2 | Zobrist hashing + depth-aware TT | `docs/v0.3.2.md`: TT preserves minimax score, 705 hits / 533 cutoffs at depth 3 |
| V0.3.3 | Negamax + PVS refactor | `docs/v0.3.3.md`: PVS score/move-identical to plain Alpha-Beta on every tested position |
| V0.3.4 | Quiescence search + check extensions | `docs/v0.3.4.md`: horizon-effect and check-resolution correctness gates, A/B benchmark recorded |
| V0.3.5 | Regression framework + tactical positions | This document + `test_search_v035.py` / `test_search_v035_beta.py`: 45/45 green |

**What the engine can do entering V0.4:** Negamax + Alpha-Beta + PVS +
iterative deepening + a depth-aware transposition table + Quiescence Search
with check extensions, all sitting on a basic material + mobility evaluation
function, at practical depths of 2-3 ply (fixed) with the horizon extended
further by Quiescence Search on tactical lines.

**What it still lacks, going into V0.4 (Advanced Evaluation):** any notion
of piece-square position tables, king safety, pawn/file structure, piece
coordination, or endgame/opening-specific knowledge — the evaluation
function is still exactly what V0.2 shipped (material value + a mobility
count). This is the natural next lever: the search infrastructure built in
V0.3 is now strong enough that a better evaluation function should translate
fairly directly into stronger play, without needing further search work
first.

**Known limitations carried into V0.4, not yet addressed:**
- Quiescence Search has no Static Exchange Evaluation (SEE) or MVV-LVA move
  ordering, so tactical leaves can be expensive on capture-heavy positions
  (see `docs/v0.3.4.md` benchmark: +300% nodes on the `initial` position at
  depth 3). Worth revisiting once V0.4's evaluation changes are in and the
  cost/benefit picture is re-measured.
- Depth 4 is still impractical (>55s from the opening position, pre-dating
  V0.3.4; not re-measured here since Quiescence Search only makes deeper
  fixed-depth searches more expensive, not cheaper).
