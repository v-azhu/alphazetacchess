# V0.5 — First Real Data Checkpoint (2026-09-04)

## What this is

Every V0.5.x doc up to this point (`v0.5.2.md`, `v0.5.3.md`,
`v0.5.4.md`) ended with some version of "the mechanism is built and
tested; a real corpus is still needed." This checkpoint is that real
corpus's first, small installment — genuinely run, not a smoke test,
but honestly still far too small to validate anything. Recorded here
mainly so the exact starting point is on the record, and so nobody
re-reads `v0.5.2.md`/`v0.5.3.md`/`v0.5.4.md` and assumes "real corpus"
means "large corpus" — it doesn't yet.

## What was run

12 real games via `tools/self_play.py` / `tools/compare_engines.py`,
depth=2, random opening (V0.5.2b defaults), collected one game at a
time due to this session's per-command execution time limit (each
depth=2 game takes 70–250s here; a handful of attempts hit the limit
mid-game and produced no record, since `append_record` only fires
after a game completes — no partial/corrupt records exist in the
file).

```
Games 1-10: SearchEngine(depth=2) self-play, no optional eval terms on either side.
  6 draws (move limit), 2 RED wins (49, 107 moves), 2 BLACK wins (108, 54 moves)

Games 11-12: tools/compare_engines.py, --a-use-endgame-heuristics vs plain depth=2.
  Game 11: BLACK_WINS (B / no-heuristic side won)
  Game 12: DRAW
```

Corpus preserved at `data/selfplay.jsonl` (12 lines) and
`data/opening_book.json` (built from it) — committed deliberately per
`data/README.md`'s own stated exception ("if you want to preserve a
specific corpus... safe to commit deliberately whenever that's
useful"). This is that case: it's the first non-empty real corpus this
project has had, worth keeping as a reference point even though it
will be superseded by larger runs.

## Running the existing tools against it

```
python tools/analyze_endgame.py --input data/selfplay.jsonl
  Loaded 12 game record(s)
  Reached endgame phase: 8/12 games
  Average endgame onset ply: 67.2
  Positions with a Rook/Cannon edge at onset: 4 (tied: 4)
    Favored side won 3/4 (75%), lost 0, drew 1
    NOTE: sample too small to draw real conclusions -- collect more self-play data before trusting this number.

python tools/build_opening_book.py --input data/selfplay.jsonl --output data/opening_book.json
  Built book: 213 unique position(s), 224 position-move entries
```

Both tools ran correctly against real (not synthetic) data for the
first time. The `analyze_endgame` result (3/4 favored-side wins) is
directionally consistent with `engine/endgame.py`'s hypothesis, and
the endgame phase (8/12 games, average onset ply 67.2) confirms games
at this depth/move-limit combination do routinely reach it — but **4
decided positions is not evidence of anything**; the tool's own
built-in caveat is exactly correct here and should be taken at face
value, not treated as a soft "well, actually it's probably fine."

The 2-game `use_endgame_heuristics` on/off comparison (1 loss, 1 draw
for the heuristic-on side) is even smaller and, if anything, points
the opposite direction from the analyze_endgame result above — which
is itself a useful reminder that a handful of games can point either
way by chance and neither should be trusted alone. `use_endgame_
heuristics` and the opening book both remain off by default; nothing
about this checkpoint changes that.

## Why this checkpoint is small, and what changed to make it real

This session's execution environment doesn't keep background
processes alive between tool calls (a `nohup ... &` launched in one
command was gone by the next command), so the originally planned
"kick off a 20-30 game batch in the background, keep working, check
back later" approach from `docs/v0.5.4.md`'s Next Step section doesn't
work here as written. Games were instead run synchronously, one game
per command with a `timeout` guard, which is why the corpus stopped at
12 rather than the 20+ games `tools/analyze_endgame.py` treats as a
reasonable threshold — each additional game costs a full round-trip at
70-250s, and this was judged a reasonable stopping point for one
checkpoint rather than spending the entire session on data collection
alone.

## Next step

Same next step as every prior V0.5.x doc, just with a real (if tiny)
head start now on record: run a much larger batch — 30-50+ games,
ideally from an environment where a long-running background process
actually is practical (a real local machine, not this session's
sandbox) — and re-run:
```bash
python tools/self_play.py --games 40 --depth 2 --max-moves 150 --output data/selfplay.jsonl
python tools/build_opening_book.py --input data/selfplay.jsonl --output data/opening_book.json
python tools/analyze_endgame.py --input data/selfplay.jsonl
python tools/compare_engines.py --a-depth 2 --a-use-endgame-heuristics --b-depth 2 --games 20 --output data/selfplay.jsonl
```
`data/selfplay.jsonl` already has 12 real games in it going into that
run — `tools/self_play.py --output data/selfplay.jsonl` appends,
so this checkpoint's data isn't wasted, just extended.
