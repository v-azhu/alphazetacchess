# V0.9.17 — Root Candidate Diagnostic

## Goal

V0.9.13–V0.9.16 progressively isolated the earlier search-score instability:

- Null Move reduced node count without changing tested decisions.
- TT and PVS A/B tests produced identical best moves and scores on the tested suite.
- Quiescence Search materially affected shallow scores and, on some positions, shallow root decisions.

V0.9.17 does not modify the engine. It exposes the relationship between static evaluation and searched root-candidate score.

## Method

For each selected position and depth:

1. Generate all legal root moves.
2. Evaluate every root move statically using the engine's current evaluation.
3. Select the top N static candidates.
4. Independently search each selected root move with a full alpha-beta window.
5. Always include the normal engine's root choice, even if it is outside the static top N.
6. Report static score, searched score, and search-minus-static delta.

The diagnostic keeps TT, PVS, Quiescence, and History enabled, with Null Move disabled.

The per-candidate diagnostic search deliberately uses a full window, so candidate comparison is not itself a root-PVS experiment.

## Run

    python tools/benchmark_root_candidates.py --positions tactical_exchange --depths 2 3 4

Then inspect the positions with earlier score instability:

    python tools/benchmark_root_candidates.py --positions initial open_position tactical_exchange --depths 3 4

For a broader candidate set:

    python tools/benchmark_root_candidates.py --positions initial --depths 3 4 --top-static 12

## Interpretation

The important signal is not simply whether search-minus-static is large. Large deltas are normal because search discovers tactics and positional consequences.

Look for:

- a high-static move with a sharply negative search delta;
- a modest-static move with a sharply positive search delta;
- candidate rankings changing substantially between depths;
- the engine's selected move being absent from the static top group;
- tactical fixtures where a clearly forced move is not recovered.

These patterns help distinguish evaluation mis-ranking, tactical horizon effects, Quiescence effects, and ordinary deeper-search correction.

## Limitation

The diagnostic searches selected root moves independently. It is a diagnostic view, not a replacement implementation of SearchEngine._search_fixed_depth. Node counts and exact timings should not be interpreted as a performance benchmark.

The current tool does not reconstruct a complete PV. A dedicated PV tracer can be added if these results reveal a candidate whose score changes materially between depths.

No engine optimization should be added until the diagnostic identifies a concrete issue.
