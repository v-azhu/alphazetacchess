## Goal and design

The suite builders consume the project's legally validated game archives. The opening builder
stores the final position after eight plies together with the eight-move `opening_prefix`, as
the paired-opening selector does. Positions are deduplicated by placement and side to move.

`tools/build_tactics_suite.py` replays archive games, samples distinct positions at plies 10–120,
and asks a local Pikafish process for MultiPV root labels. The top five root moves are searched to
the requested depth (25 by default); each remaining legal move is searched with a forced-root
search at a configurable lower depth (2 by default). The remaining moves are constrained with
`searchmoves` and searched together in one MultiPV call, avoiding one separate process search per
move. Every score and its actual depth are stored. This lower-depth remainder is the explicit
performance compromise allowed by the work-package prompt; it is not equivalent to having every
legal move searched to depth 25.

`tools/eval_tactics.py` independently verifies the stored legal-move set, then supports the
Python `SearchEngine`, a UCI process, and the first generated legal move. It reports solve rate
(the selected move is among the depth-qualified best-scoring moves), blunder rate (centipawn loss
at least 300), and mean centipawn loss.

## AZ-TAC-500 owner-approved category definitions

The categories are exclusive, assigned in the order below, and are sampled to the 300/200 split
using `SHA-256(full FEN) mod 5` (three fifths dev, two fifths test). The selected position's
category and split quotas are respectively 60/40, 90/60, 90/60, 30/20 and 30/20:

1. **Mate in 1–3:** a depth-qualified top move reports a positive Pikafish mate distance of one
   through three.
2. **Only-move defense:** the best depth-qualified score is at least 0 cp, and every other legal
   move scores at least 300 cp below it.
3. **Avoid-blunder:** at least three of the first five legal moves in the engine's generated order
   score at least 300 cp below the best move. This gives “top-5” a deterministic interpretation
   independent of the teacher's ranking.
4. **Win material:** the best depth-qualified move scores at least +300 cp.
5. **Endgame:** no more than eight non-king pieces remain on the board.

The owner reviewed and approved these operational definitions, including the deterministic
interpretation of “top-5” as the first five legal moves in engine-generated order and the
eight-piece endgame cutoff. These definitions are the owner-approved category rules for this suite.

## Owner runbook

Run from the repository root in PowerShell. Pikafish and its network are external inputs and are
not included in the repository.

1. Regenerate the balanced opening set using Pikafish (11,786 depth-12 evaluations on the current
   archive; runtime depends on the owner's machine and Pikafish build):

   ```powershell
   python tools/build_opening_suite.py `
     --input trainingdata/wxf-41743games.zip trainingdata/dpxq-99813games.zip `
     --pikafish-path .\pikafish.exe --network-path .\pikafish.nnue `
     --eval-depth 12 --count 2000 --seed 0 `
     --output data/suites/openings_8ply_v1.json `
     --manifest data/suites/openings_8ply_v1.manifest.json
   ```

2. The 20-position real-label smoke run completed successfully. It returned all legal-move
   labels for all 20 positions, with top moves at depth 25 and the remaining moves at depth 2.
   The report is stored outside the repository because it is a smoke artifact, not the 500-position
   suite. To repeat it:

   ```powershell
   python tools/build_tactics_suite.py --label-smoke --smoke-count 20 --threads 4 `
     --pikafish-path .\pikafish.exe --network-path .\pikafish.nnue `
     --top-depth 25 --rest-depth 2 `
     --output data/suites/az_tac_20_pikafish_smoke.json
   ```

   The optimized builder labels the remaining legal moves together in a lower-depth MultiPV
   search rather than launching a separate search for each move. The single-position check in this
   environment took 78.1 seconds with four Pikafish threads; the previous 20-position run used the
   earlier single-thread labeling path. A crude extrapolation from the new one-position sample is
   about 10.8 hours for 500 positions alone, not accounting for extra candidates needed to fill all
   category/split quotas. This is not a measured full-run estimate; measure on the owner's machine.
   The full builder can label more than 500
   candidates while it fills the category/split quotas; it records that number as
   `candidate_positions_labeled`. Estimate its runtime from
   `20-position elapsed time × candidate_positions_labeled / 20`, then replace the estimate with
   the measured full-run time in the acceptance report.

3. Label the fixed AZ-TAC-500 suite. The builder now writes a durable JSONL checkpoint
   after every labeled candidate (flush + fsync). The default path is
   `data/suites/az_tac_500.json.checkpoint.jsonl`; it is intentionally retained after success
   and after a quota failure. Re-run the exact same command to resume. The checkpoint is bound to
   the candidate fingerprint, target quotas, Pikafish binary/network hashes, depths, thread count,
   and platform; incompatible checkpoints are rejected rather than silently reused. Use
   `--checkpoint <path>` to choose another path, or `--restart` only when you deliberately want
   to discard prior checkpoint data. An interrupted final JSONL record is discarded safely.

   ```powershell
   python tools/build_tactics_suite.py `
     --input data/external_games.jsonl `
     --pikafish-path .\pikafish.exe --network-path .\pikafish.nnue `
     --threads 4 `
     --top-depth 25 --top-moves 5 --rest-depth 2 `
     --output data/suites/az_tac_500.json
   ```

   If the fixed targets still cannot be filled, the checkpoint remains available and the error
   now includes per-category/per-split qualification counts. Re-running with the same settings
   will reuse cached classification results rather than spend hours searching again. Do not relax
   category thresholds just to fill quotas; inspect those counts first.

4. Record the Python V0.10 baseline and first-generated-move baseline at each fixed budget. The
   search tool uses a depth-64 ceiling with a timer, matching the historical time-limited search
   configuration; the first-move baseline is deterministic and does not need Pikafish:

   ```powershell
   python tools/eval_tactics.py --suite data/suites/az_tac_500.json --engine-spec search --engine-config '{"depth":64}' --time-ms 100 --output data/suites/v0.10_az_tac_500_100ms.json
   python tools/eval_tactics.py --suite data/suites/az_tac_500.json --engine-spec first --time-ms 100 --output data/suites/first_move_az_tac_500_100ms.json
   python tools/eval_tactics.py --suite data/suites/az_tac_500.json --engine-spec search --engine-config '{"depth":64}' --time-ms 500 --output data/suites/v0.10_az_tac_500_500ms.json
   python tools/eval_tactics.py --suite data/suites/az_tac_500.json --engine-spec first --time-ms 500 --output data/suites/first_move_az_tac_500_500ms.json
   python tools/eval_tactics.py --suite data/suites/az_tac_500.json --engine-spec search --engine-config '{"depth":64}' --time-ms 2000 --output data/suites/v0.10_az_tac_500_2000ms.json
   python tools/eval_tactics.py --suite data/suites/az_tac_500.json --engine-spec first --time-ms 2000 --output data/suites/first_move_az_tac_500_2000ms.json
   ```

- The 20-position committed smoke file uses deterministic synthetic labels and must never be used
  to report a solve rate or strength result.
