# V0.9.12 — Conservative Null Move Pruning

## Goal

Test whether Null Move Pruning can reduce the alpha-beta search tree without
changing the evaluation function or the existing move-ordering algorithms.

## Design

Null Move is optional and disabled by default:

```python
SearchEngine(use_null_move=False)
```

The first implementation is deliberately conservative:

- only active when alpha-beta is enabled;
- never used at the root;
- requires `depth >= 3`;
- uses reduction `R=2` by default;
- requires more than one legal move;
- disabled while in check;
- disabled below a configurable material-count threshold (`7` pieces by default);
- the null search itself cannot immediately perform another null move.

The null move changes only the side-to-move component of the board state. The
board provides `null_move()` / `undo_null_move()` rather than treating a null
move as a normal Xiangqi move.

## Why conservative?

Null Move Pruning is a forward-pruning technique. Unlike ordinary alpha-beta
optimization, it can theoretically discard a branch that contains a useful
move. Xiangqi also has endgame and zugzwang-like positions where the assumption
behind Null Move is less reliable. Therefore the first implementation is an
A/B experiment, not an unconditional claim of strength improvement.

## Benchmark

Run the basic A/B benchmark:

```powershell
python tools/benchmark_null_move.py --depth 4
```

Run the broader regression-oriented suite:

```powershell
python tools/benchmark_null_move_suite.py --depth 4
```

The benchmarks compare identical engines with only `use_null_move` changed.
They report elapsed time, searched nodes, NPS, score, selected move, and
Null Move diagnostics. The suite additionally covers an ordinary starting
position, an open position, a tactical material position, a small endgame,
and a side-in-check position.

The suite is a regression signal, not a standalone strength test. In
particular, identical best moves on a small hand-built set do not prove that
Null Move improves playing strength.

## Observed depth-4/5 A/B results

The user's local depth-4 benchmark produced:

- initial position: 15,130 -> 11,531 nodes (-23.8%); 5.142s -> 3.798s;
  score and move unchanged;
- capture-rich position: 1,237 -> 1,237 nodes; score and move unchanged.

The user's local depth-5 benchmark produced:

- initial position: 104,845 -> 91,326 nodes (-12.9%); 26.370s -> 23.104s;
  score and move unchanged;
- capture-rich position: 2,590 -> 2,590 nodes; score and move unchanged.

These results establish a useful search-cost reduction in the tested initial
position while not establishing a general playing-strength improvement.

## Acceptance criteria

The feature should be kept only if testing shows a meaningful reduction in
search cost while tactical correctness and move quality remain stable.
A lower node count alone is not sufficient evidence of stronger play.

## Current status

The basic depth-4 and depth-5 A/B benchmarks are positive for search-cost
reduction on the initial position. The next validation step is the broader
`tactical/endgame` suite, followed by human-vs-engine A/B tests through the
Web UI. Null Move remains disabled by default until those checks are complete.

If the broader suite exposes tactical regressions, keep the feature available
for experiments but disabled and revisit its guards before moving on.
