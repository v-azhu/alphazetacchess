# V0.3.1 Benchmark Protocol

## Purpose

V0.3.1 is not considered complete until the optimization is measured.

The benchmark compares:

1. V0.2-style fixed-depth Alpha-Beta
2. V0.3.1 iterative deepening + root move ordering

at the same maximum search depth.

## Metrics

Record:

- elapsed time
- total nodes
- nodes per second (NPS)
- final search score
- best move
- completed depth

For iterative deepening, `nodes` includes all completed iterations from depth 1 through the requested depth. This is intentional: it measures the actual total work performed.

## Correctness Gate

For each benchmark position and depth:

- fixed and iterative search should return the same score;
- fixed and iterative search should return the same chess move.

A mismatch is treated as a correctness regression.

## Commands

Run the default benchmark:

    python tools/benchmark_search.py

Depth 2 and 3:

    python tools/benchmark_search.py --depths 2 3

Repeat each case:

    python tools/benchmark_search.py --depths 2 3 --repeat 2

Save machine-readable results:

    python tools/benchmark_search.py --depths 2 3 --output benchmark_v031.json

## Interpretation

Do not judge the optimization from node count alone.

We care about:

    correctness
        +
    nodes
        +
    NPS
        +
    wall-clock time

Iterative deepening necessarily repeats shallower searches. Therefore it may use more total nodes than a single fixed-depth search even when its move ordering makes the final-depth Alpha-Beta tree smaller.

The important V0.3.1 question is whether the ordering provides enough pruning benefit to make deeper search more practical, while producing exactly the same search result.

## Handoff

After the benchmark is run locally:

1. Record the actual measurements in `docs/roadmap.md`.
2. Mark V0.3.1 Benchmark complete.
3. Commit the benchmark tool and measured results.
4. Start V0.3.2: Transposition Table.
