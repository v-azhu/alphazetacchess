# V0.9.13 — Search Strength Validation

## Goal

Stop adding search optimizations blindly and first measure how the current
engine's decision changes as search depth increases. The purpose is diagnosis:
identify search instability, large score swings, and positions that deserve
tactical investigation before choosing the next algorithmic change.

## Diagnostic tool

Run from the repository root:

```powershell
python tools/benchmark_search_stability.py --depths 2 3 4
```

For a deeper run:

```powershell
python tools/benchmark_search_stability.py --depths 3 4 5
```

The tool currently samples three representative positions already used by the
Null Move regression suite: the initial position, an open position, and a
small tactical-material position.

For each depth it records:

- elapsed time;
- searched nodes and NPS;
- score;
- selected move;
- whether the selected move changed from the previous depth;
- score change from the previous depth.

`--null-move` is available as an explicit diagnostic switch, but the default
run keeps Null Move disabled so the baseline search can be studied separately.

## Interpretation

A move change at greater depth is not automatically a defect. Deeper search can
legitimately discover a better continuation. The useful warning signs are
repeated instability, unusually large score swings, or tactical positions whose
choice remains poor despite deeper search.

This tool does not assign an Elo score or claim that one depth is "stronger" in
all positions. It provides evidence for selecting the next engineering target.

## Current status

V0.9.12 Null Move validation showed about 21.5% node reduction at depth 4 and
21.8% at depth 5 across the five-position regression suite, with no changed
score/best-move result. The suite also correctly produced zero Null Move
attempts in the guarded small-endgame and in-check positions.

Those results justify keeping Null Move as an experimental optimization, but
do not yet justify making it the default. V0.9.13 therefore focuses on search
stability and tactical diagnosis before another major search optimization is
introduced.

## Next checkpoint

1. Run the stability benchmark at depths 2-4.
2. Run depths 3-5 if runtime is acceptable.
3. Record positions where the best move repeatedly changes or the score moves
   sharply.
4. Use those concrete positions for tactical regression tests and Web UI
   human-vs-engine analysis.
5. Choose the next search/evaluation change from observed failure modes rather
   than from algorithm accumulation alone.
