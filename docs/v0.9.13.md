# V0.9.13 — Search Strength Validation

## Goal

Stop adding search optimizations blindly and first measure how the current
engine's decision changes as search depth increases. The purpose is diagnosis:
identify search instability, large score swings, and positions that deserve
tactical investigation before choosing the next algorithmic change.

## Diagnostic tool

Run from the repository root:

```powershell
python tools/benchmark_search_stability.py --depths 2 3 4
```

For a deeper run:

```powershell
python tools/benchmark_search_stability.py --depths 3 4 5
```

The tool currently samples three representative positions already used by the
Null Move regression suite: the initial position, an open position, and a
small tactical-material position.

For each depth it records:

- elapsed time;
- searched nodes and NPS;
- score;
- selected move;
- whether the selected move changed from the previous depth;
- score change from the previous depth.

`--null-move` is available as an explicit diagnostic switch, but the default
run keeps Null Move disabled so the baseline search can be studied separately.

## Local results

The current local runs were performed with Null Move disabled.

### Initial position

Depth 2 → 3 → 4 → 5 selected `(1, 0)->(2, 2)` at every depth.
The score was `0 → 100 → 0 → 60`. Thus the root move is stable in this sample,
while the numerical score changes materially as the horizon increases.

### Open position

Depth 2 → 3 → 4 → 5 also selected `(1, 0)->(2, 2)` at every depth.
The score was `0 → 100 → 0 → 100`. Again, the root move is stable while the
score oscillates.

### Tactical exchange

Depth 2 selected `(1, 2)->(3, 3)` with score `0`.
Depth 3 changed to `(4, 2)->(4, 6)` with score `190`, and that move remained
stable at depths 4 and 5. The score then moved `190 → 0 → 100`.

This demonstrates why a depth-2/3 move change is not automatically a defect:
the deeper search converged on one root move in the tested position.

## Interpretation

There are two useful signals.

First, the root decision is stable on these samples: the initial and open
positions agree at all four depths, and the tactical position agrees from depth
3 onward.

Second, the numerical evaluation is substantially less stable than the root
move. All three samples show changes of roughly one pawn-sized unit or more
between adjacent depths. This is not enough evidence to call the evaluation
incorrect, because horizon effects and different tactical continuations can
legitimately change the score. It is, however, enough evidence to make score
stability and tactical resolution a useful next investigation target.

These three positions are not a general strength test and do not identify a
specific evaluation defect. They establish a baseline for the next tactical
regression stage.

## Relationship to V0.9.12

The Null Move regression suite showed approximately 21.5% node reduction at
depth 4 and 21.8% at depth 5 across five positions, with no changed score or
best-move result. It also produced zero Null Move attempts in the guarded
small-endgame and in-check positions.

Those results justify keeping Null Move as an experimental optimization, but
do not yet justify making it the default. V0.9.13 therefore keeps the baseline
search isolated while we investigate concrete tactical behavior.

## Next checkpoint

Build a curated tactical FEN suite with independently validated expected
results where possible (mate, material outcome, or known best move). Use it at
multiple depths to distinguish among:

1. search failing to see a tactic;
2. evaluation preferring the wrong material or positional outcome;
3. quiescence failing to stabilize tactical positions;
4. move ordering changing performance without changing the result.

Only after those tests should another major search/evaluation change be selected.
