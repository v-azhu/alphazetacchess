# AlphaZetaChess V0.4.3 — Mobility Evaluation (Alpha)

## Objective

Add mobility as the next independent evaluation signal after PST (V0.4.1)
and King Safety (V0.4.2).

## Design

The first checkpoint intentionally introduces `engine/mobility.py` without
changing `engine/evaluation.py` or `SearchEngine`.

Mobility is measured from fully legal moves, not pseudo-legal moves. This means
self-check and flying-general constraints are already respected.

The initial signal is:

- King / Advisor / Elephant / Pawn: 1 point per legal move
- Horse / Cannon / Rook: 2 points per legal move

The weights are deliberately conservative and are not claimed to be tuned
playing-strength values.

## Why split this into two checkpoints?

Mobility runs at every leaf and calls legal move generation. It can therefore
be considerably more expensive than the existing material/PST/king-safety
terms. We should first verify:

1. the signal is symmetric;
2. the signal reacts in the expected direction;
3. the implementation does not accidentally introduce illegal-position
   assumptions;
4. the performance cost is measurable.

Only then should it be wired into `evaluate()` and exposed through
`SearchEngine(use_mobility=True)`.

## Acceptance for V0.4.3-alpha

Run the full test suite. The new mobility tests must pass together with all
existing tests.

## Next checkpoint

If green:

1. benchmark mobility calculation cost;
2. wire `mobility_balance()` into `evaluate()`;
3. add a `use_mobility` A/B flag;
4. add evaluator regression tests;
5. run a small engine benchmark against V0.4.2.
